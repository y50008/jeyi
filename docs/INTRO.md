# memory-brain-agent · 介绍

> 给 AI 助手一套**记得住、找得回、改得口**的长期记忆：
> 每轮只注入 300 字，记住一个人一年的事。
>
> 哲学：发现现成的，超越现成的——**超越必须接受检验**。

---

## 它解决什么问题

对话型 AI 的三个长期痛点：

1. **超出上下文就失忆**。聊到第 80 轮，前面说过的话被截掉，助手开始问你已经回答过的问题。
2. **超长上下文很贵**。为了"都记得"，每轮把几万字历史重发一遍，token 费是 O(轮次²)。
3. **改口改不掉**。你说"我改喝普洱了"，旧偏好还躺在上下文里，模型时对时错地混着说。

memory-brain 的答案是：**把记忆从上下文里搬出来，变成一张可检索的图**。
每轮只按相关度挑几条（≤300 字）注入，其余留在库里。上下文长度与记忆总量解耦。

## 它长什么样

```
你 → on_message ──► 分词/情绪/日期/实体 ──► 节点 + 边 + 状态机
                                              │ 事件溯源（append-only）
                                              ▼
你 ← before_reply ◄── 预算选包 ◄── 倒排索引 + 向量 + 图扩散
```

一条记忆是一张卡，三个通道：

| 通道 | 内容 | 作用 |
|------|------|------|
| gist | 一句话轮廓 | 注入的主体，衰减慢 |
| verbatim | 用户原话 | 只在"刚被改口"或"问的就是这句"时附带，防模型把记忆讲歪 |
| feeling | 情绪标签/效价/唤醒度/原因 | 7 天半衰，影响召回排序 |

## 数字（都是跑出来的，不是估的）

**中文检索基准**（自建语料 + 独立留出集，`tools/bench.py`）：

| | 纯词法（零依赖） | + 稠密（24MB 本地模型） |
|---|---|---|
| 主集 rank@5（53 问，用于调参） | 96.2% | **98.1%** |
| 留出集 rank@5（27 问，改写问法，只跑一次） | 77.8% | **85.2%** |
| 越界问题弃答（不该硬凑的别凑） | 100% | 100% |
| 每轮注入字符 | 36.5 | 43.3 |
| 检索延迟（52 条记忆） | 0.2 ms | 2.8 ms |

**公开基准**（语料由外人提供，`tools/bench_external.py`）：

| 基准 | 词法 | + 稠密 |
|---|---|---|
| LoCoMo（1986 问，证据是"某一轮对话"） | 48.6% | **50.9%** |
| LongMemEval-S（50 问，证据是"整段会话"） | 92.0% | **96.0%** |

**长时程**（虚拟时钟跑一年，`tools/simulate.py`）：核心记忆 3/3 仍在，
随口一提的小事 17/18 归档，归档后常规检索取不到、但"你还记得…吗"能 18/18 取回，
两条承诺分别在到期前一天被主动提起。

> 这些数字怎么看，写在 [docs/VALIDATION.md](VALIDATION.md) 里，包括**没做到的**：
> 语料是合成的、LongMemEval 只跑了 50 问、检索命中不等于答对。

## 三个关键设计取舍

**1. 门控作用在相关度上，不作用在分数上。**
早期版本用 `C = s/(s+8)`，会饱和——单个关键词命中永远过不了 0.2 的地板，
"我家猫叫什么"检索不到"我养了一只猫叫团子"。改成 tf-idf 余弦后阈值才可标定。

**2. 融合用名次，不用分数。**
稠密余弦和词法余弦不在一个尺度，取 max 会让稠密单方面覆盖词法的正确排序
（实测主集 96.2 → 86.8，弃答 100% → 0%）。改用加权 RRF，稠密只当"少数票"。

**3. 「弃答」和「故障」必须分开。**
引擎说"没有"是特性；说"连不上"才是故障。混在一起会让一次正常弃答触发整体降级。

## 和别的方案比

| | 整段历史塞上下文 | 粗暴摘要 | 向量库 RAG | memory-brain |
|---|---|---|---|---|
| 每轮成本 | O(历史) 增长 | 固定但丢细节 | 固定 | **固定 300 字** |
| 能改口 | 差 | 差 | 一般 | **状态机：superseded/overturned** |
| 能遗忘 | 不能 | 不能 | 需手动删 | **半衰期归档 + 可显式召回** |
| 可审计 | 难 | 难 | 难 | **事件溯源，每步可回放** |
| 会硬凑 | 是 | 是 | 是 | **弃答率可测（100%）** |

## 谁适合用

- 想要**长期陪伴型对话**（个人助理、角色、宠物）而不是单次问答的开发者；
- 在意 **token 成本**、需要一个硬预算上限的人；
- 需要**可解释**（为什么注入了这条）和**可回放**的人；
- 中文场景优先（分词、情绪词表、日期解析都是中文原生的）。

## 谁不适合

- 只有几轮对话的短问答（直接塞上下文更简单）；
- 需要跨用户共享知识库（这是个人记忆，不是知识库）；
- 要求"永不忘事"的场景——这里会主动遗忘，只是保证能翻回来。

## 工程特点

- **核心零依赖**（纯标准库）。稠密检索是可选层，装上 `numpy/onnxruntime/tokenizers` 才加载；
- **40 项测试**，每一条对应一个具体缺陷（见 [docs/FIXES.md](FIXES.md)，B1–B31）；
- **三道质量门禁**：主集、留出集、一年长时程；
- **两个公开基准**接入脚本，语料可换（LongMemEval / LoCoMo）；
- MIT，可商用；打分结构与常数校准自 `Anarrogantcat/dsh-identity`（MIT，已署名）。

## 已经能接的东西

- **大肥鱼（dsh-identity）**：替换它 `lib/memory.js` 的选层，
  实测多跳问句从 0/1 变成 1/1，面板与全量卡不受影响。见 [integration/dsh-identity](../integration/dsh-identity/README.md)。
- **任何 Python Agent**：四个钩子（写入/检索/回响/结算）。
- **任何语言**：`python -m brain.serve` 起本地 HTTP 侧车，REST 接入。
